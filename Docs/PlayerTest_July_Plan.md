## 1. 测试目标（测什么）

回答设计评审第 14 条一直未验证的问题：**指挥宠物采集、捕捉、战斗、打 Boss，到底好不好玩。** 首轮只验证局内核心循环的乐趣与手感；元层的"带入带出/永久损失"张力是第二层，留到地基验证为好玩之后再测。

## 2. 关键前提：站在 M1 上，不从零搭

现有 `AMFGameMode` 的 M1 循环**本身就是单局闭环**：`BeginPlay → 抓宠阶段 → 打 Boss → 胜负结算 → RestartGame 重开`（[MFGameMode.cpp:28](../Source/ProjectMF/GameLoop/Private/MFGameMode.cpp#L28)）。结算 UI（`ResultOverlay`）、胜负事件（`OnGameResult`）已就位，且本就无存档。玩家测试版 = 在 M1 上叠 Loop2 内容层，**元层本就不在 M1 里，砍掉零损失**。

## 4. 一局玩家体验

进图（带 2–3 只固定初始宠）→ 探索大地图：采集资源、捕捉野宠扩队、打野怪 → 用采集的资源**合成宠物食物/药**（治疗零食、力量零食）→ **喂宠续航/变强** → 挑战 Boss 或撤离 → 胜负/成果结算 → 重开。

## 6. 风险与保底

- **缓冲很小**：约 19 工作日刚好填满，任一块超期就吃 W4 打磨时间。
- **三个技术风险点**：背包数据重构可能回归影响捡取/召唤；打造需放开 `AddResource` 接受 Consumable（别弄坏现有资源叠加）；A3 地图扩造+平衡是"手感活"最易超预期。
- **保底策略**：W3 吃紧时优先砍"撤离点"（只留打 Boss 结束）+ 简化地图；**绝不压缩 W4 打磨**——宁可内容少，也要玩到的部分是顺的。
